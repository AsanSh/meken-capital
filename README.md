# Meken · meken.im

Портал ОсОО «Адвестор»: каталог реальных активов, заявки инвесторов, доступ к документам, голосования, уведомления и администрирование. Один интерфейс и серверная база SQLite. Node.js 24.12+; для работы приложения не нужны сторонние npm-зависимости.

## Запуск

```sh
npm run setup
npm start
```

Открыть http://127.0.0.1:4173/. Администратор: http://127.0.0.1:4173/#admin-login. Email partner@meken.im; уникальный пароль генерируется в приватном .env (не входит в Git и архив). Изменение ADMIN_PASSWORD после первого запуска не меняет существующий пароль: используйте настройки кабинета.

Не запускайте Python static server: старые HTML-макеты не являются рабочей версией. Сервер выдаёт только новый интерфейс и публичные ресурсы; старые адреса перенаправляются в него.

Восстановление пароля оператором после проверки личности: `node --env-file-if-exists=.env scripts/reset-password.mjs user@example.com`. Команда отзывает все сессии и сохраняет новый случайный пароль в закрытом файле внутри data/. Пароль не печатается в консоль. Передать владельцу безопасным способом и удалить временный файл после передачи.

## Публикация на meken.im

1. Нужен Linux VPS с Docker Compose, постоянным диском и открытыми портами 80/443. GitHub Pages не исполняет этот сервер.
2. Скопировать пакет проекта и приватный .env. Задать APP_ORIGIN=https://meken.im, NODE_ENV=production, уникальные ADMIN_EMAIL/ADMIN_PASSWORD.
3. Направить A-записи meken.im и www.meken.im на IP VPS. Если задана AAAA, она также должна вести на этот VPS.
4. Выполнить `docker compose up -d --build`. Caddy получает HTTPS-сертификат и перенаправляет www на основной домен.
5. Проверить /api/health, вход, регистрацию и загрузку PDF; создать первый проект и опубликовать после проверки документов.

База находится в volume meken-data. Не удалять volumes при обновлении. Повторная сборка сохраняет базу. Для резервной копии: `docker compose exec app node scripts/backup.mjs`; результат в volume meken-backups. Настройте ежедневный запуск этой команды на VPS и вынос копий с сервера. Восстановление проверять на отдельном окружении при остановленном приложении, с сохранением прав доступа к БД.

## Сборка и проверка

```sh
npm ci
npm test
npm run build
```

Пакет dist/meken содержит рабочий сервер, интерфейс и инструкции. Секреты, данные и старые макеты исключены. Docker-сборка требует запущенного Docker daemon; локальная проверка Node не заменяет проверку контейнера на сервере.

## Что работает

- Регистрация и вход; scrypt-хэши, HttpOnly cookie, выход и смена пароля с отзывом всех сессий; серверные роли.
- Каталог, поиск, фильтры, сценарный калькулятор, выбор на устройстве, официальный KGS/USD из НБКР с датой. Сервер проверяет курс раз в час; при недоступности источника показывает последний сохранённый курс с пометкой.
- Заявка на опубликованный проект с согласиями, защита от повторной заявки, статусы и допуск.
- PDF до 5 МБ: хранение на сервере, выдача только администратору и допущенным пользователям.
- Голосования допущенных пользователей: один ответ, срок закрытия, журнал.
- Персональные уведомления, хронология, подбор по сумме/сроку.
- Администратор создаёт и редактирует проекты, загружает документы, публикует, обрабатывает заявки, создаёт вопросы для голосований.
- Публикация требует четырёх типов документов и имени проверяющего. Редактирование снимает публикацию.
- Журнал входов, согласий, публикаций, решений, загрузок и голосов.

## Граница готовности

Рабочая платформа заявок и сопровождения. Заявка и допуск не означают внесение капитала. Реальные договоры, деньги, KYC/AML и шариатская проверка выполняются оператором вне интерфейса. В личном кабинете нет вымышленных портфелей и дохода.

Пустая база запускается без действующих предложений. Каталог показывает помеченные примеры экономики; подать на них заявку нельзя. До реальной публикации оператор загружает достоверные материалы. Наличие PDF не означает автоматическую проверку содержания.

Исходящая почта и автоматическое подтверждение email не настроены. Уведомления доставляются внутри кабинета. Ящик partner@meken.im нужно создать у почтового провайдера. Восстановление доступа выполняется оператором после проверки личности. Перед сбором данных указать в политике фактического хостинг-провайдера и страну размещения; юридические тексты требуют финализации оператором.

Интеграция Planalytic, платежи, электронная подпись, внешняя идентификация и юридически взвешенные голоса не реализованы: нужны конкретные провайдеры, договоры и API. Текущий интерфейс не имитирует эти функции.

## Продолжение
