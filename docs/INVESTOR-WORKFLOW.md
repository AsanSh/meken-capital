# Пул инвесторов и обработка заявок

## Реализовано

- Регистрация и профиль: USD/KGS, суммы по альтернативным горизонтам до 6, 7–24 и более 24 месяцев, готовность 7/14/30 дней, направления, необязательный WhatsApp.
- Отдельное добровольное согласие на включение в пул и контакт по подходящим проектам. Только согласившиеся отображаются в пуле оператора. Горизонты и валюты не складываются.
- Заявки на Беш-Кунгей / Оскон Ордо: сумма USD, вариант, срок готовности; повторная отправка обновляет существующую заявку и возвращает на первичное рассмотрение.
- Кабинет: статус, сообщение оператора, отзыв заявки.
- Админка: первичная заявка, обсуждение, проверка документов, согласованные условия, отказ; сообщение инвестору, приватная заметка и дата следующего контакта.
- Смена этапа создаёт уведомление в кабинете. Приватные заметки не возвращаются в API инвестора. Устаревшее сохранение администратора отклоняется с HTTP 409.

## Где найти

- `/#register` — регистрация с анкетой.
- `/#profile` — изменение готовности / отзыв согласия на пул.
- `/#account` — заявки и статусы.
- `/#admin` — пул и обработка, только для существующей роли admin.

## Границы

WhatsApp сейчас контакт, НЕ OTP-аутентификация. Формат email проверяется, владение ящиком не подтверждается письмом. Эти интеграции требуют настройки провайдеров.

Ни согласование условий, ни проверка документов не подтверждают договор, соответствие шариату, такафул или поступление денег. Учет подписанных договоров и банковских операций, платная подписка, строительная отчётность и индивидуальный калькулятор таунхаусов остаются отдельными этапами. Дата следующего контакта сохраняется оператору, автоматической рассылки нет.

## Технические детали

Новый UI: `site/investor-workflow.js`. Анкета сохраняется в существующий `investor_profiles.payload`. Новая таблица `project_interest_workflow` создаётся без изменения или удаления существующих таблиц; для старых заявок статус по умолчанию `new`.

API: POST `/api/admin/project-interest`, POST `/api/project-interests/withdraw`; существующие GET заявок дополнены статусами. Операции проходят через действующие транзакции, CSRF-проверки и проверку роли. Повторная отправка не считается новым поступлением средств.

Проверки: `npm test`, `npm run build`; PostgreSQL — `node --env-file=.env.vercel.production scripts/test-postgres.mjs` (отдельная временная схема).
