# Передача Meken
Обновлено 6 сентября 2026. Домен **meken.im**, контакт **partner@meken.im**. Оператор ОсОО «Адвестор», Бишкек, Тыналиева 26/1.

## Рабочие исходники
- server.mjs: Node HTTP + SQLite, сессии/роли, заявки, проекты, PDF, голоса, уведомления, аудит.
- site/app.html, site/portal.css, site/portal.js: единый интерфейс. Hash-навигация сохраняет шапку и историю.
- site/concepts/model.js: только примеры экономики и функция расчёта. Примеры не публикуются и не принимают заявки.
- scripts/: подготовка уникального пароля, резервная копия, сборка.
- Dockerfile, compose.yaml, Caddyfile: VPS-развёртывание с HTTPS и постоянной БД.
- tests/server.test.mjs, tests/portal.test.cjs: активные проверки; старые отдельно в test:legacy.

## Состояние
Начальная база пуста. Bootstrap создаёт администратора из приватного .env. Не публиковать его содержимое. Финансовые операции не изображаются как проведённые. Заявки означают интерес; approved открывает документы.

Старый Python static server заменить npm start. Старые страницы перенаправляются в новый интерфейс. Доступ к старым JS, тестовым паролям и статическим административным данным закрыт allowlist сервера.

## Внешняя настройка
Нужны хостинг с постоянным диском, DNS meken.im, почтовый ящик, фактические реквизиты размещения в политике, проверенные документы и процедура допуска. Контейнер следует проверить на VPS. Не заявлять о публичном запуске до его проверки.

## Архитектурные границы
Один экземпляр и локальная SQLite. Для масштабирования нужна общая БД. Rate limit в памяти одного процесса. Внешняя почта, email verification, MFA, e-sign, банковская сверка, Planalytic API и KYC-провайдер не подключены. Администратор проверяет PDF вручную. Голос фиксирует мнение; веса и кворум договора не автоматизированы.

Публикация требует asset/finance/contract/sharia документов и имени проверяющего; эти поля не являются сертификатом. Изменение карточки снимает её с публикации. Версия записи предотвращает потерю изменений при одновременном редактировании.
