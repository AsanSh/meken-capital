# Техническое задание. Портал Meken Capital

Версия 0.1 · 3 сентября 2026 · черновик для обсуждения с юристом и разработчиком

## 1. Цель

Портал для венчурного управляющего, который привлекает квалифицированных инвесторов
и бизнес-ангелов (в первую очередь кыргызскую диаспору в США) в сделки:

- стройка домов с котлована, квартиры ниже рынка с ремонтом и продажей;
- закупка стройматериалов в межсезонье и рассрочка материалов подрядчикам с раскрытой наценкой;
- доли в строительных технологических компаниях (Planalytic, Ustalar, Safinat).

Все сделки — на исламских принципах: без ссудного процента, с делением прибыли и убытка.
Портал должен решать главную проблему инвестора на расстоянии — контроль: где деньги,
что с объектом, кто и когда что подписал.

## 2. Правовые ограничения, определяющие продукт

Источник: Закон КР «О венчурном финансировании» № 126 от 28.07.2026; Закон КР «Об инвестиционных фондах» № 92 от 26.07.1999 (ред. 2026). Подробнее — `legal-architecture.md`.

| Ограничение | Следствие для портала |
|---|---|
| Запрет рекламы фонда, публичной оферты и выступлений для неограниченного круга лиц в период сбора капитала (ст. 10.1) | Публичный сайт не показывает действующие сделки, целевую доходность, минимальные чеки. Каталог сделок — только за логином после подписания договора фонда. |
| Только квалифицированные инвесторы и бизнес-ангелы (ст. 9.12, 9.14) | Обязательный шаг подтверждения статуса до доступа к сделкам. Фиксация документов и даты подтверждения. |
| Информация о фонде на сайте управляющего после закрытия сбора — не реклама (ст. 10.2) | Публично — только завершённые сделки с фактическим результатом. |
| Ежеквартальные отчёты участникам, годовой аудит (ст. 8.6–8.7) | Модуль отчётности с обязательным квартальным циклом. |
| Фидуциарные обязанности, недопущение конфликта интересов, раскрытие (ст. 8.3) | Реестр связанных компаний; сделки с ними — только после уведомления и голосования участников. |
| Идентификация инвесторов и проверка источника средств (ст. 15.3) | KYC/AML-модуль: документы, источник средств, журнал проверок. |
| Вызов капитала под сделку (ст. 8.5) | Деньги не собираются заранее; капитал вызывается под подписанную сделку. |
| Исламские принципы (внутреннее требование) | Заключение шариатского совета — обязательный артефакт до вызова капитала. Нет депозитов под процент, нет конвертируемых займов, нет гарантий дохода — ни в тексте, ни в интерфейсе. |

## 3. Роли

| Роль | Кто | Что видит и делает |
|---|---|---|
| Гость | любой посетитель | Публичный сайт. Форма запроса приглашения. |
| Кандидат | запросил приглашение | Статус заявки, загрузка документов для подтверждения статуса КИ/ангела и KYC. Сделок не видит. |
| Участник | подписал договор фонда | Каталог действующих сделок, участие, портфель, движение средств, отчёты, голосования, доска предложений. |
| Управляющий | венчурный управляющий и его сотрудники (роли внутри: аналитик, технадзор, комплаенс, бухгалтер) | Админка: создание и ведение сделок, вызовы капитала, отчёты, распределения, реестр участников. |
| Шариатский совет | внешние консультанты | Просмотр структуры сделки, загрузка заключения, статус «одобрено / на доработку». |
| Аудитор | внешний | Только чтение: движение средств, документы, журнал действий. |

## 4. Публичный сайт (`site/`)

Готов. Страницы: главная, управляющий, принципы, закрытые сделки, вопросы, запрос приглашения, вход, правовая информация, английская версия.

Правила контента, обязательные к соблюдению при любых правках:
- Нет целевой доходности, минимальных чеков, действующих сделок, слов «гарантия», «фиксированный доход».
- Каждая страница несёт баннер о статусе КИ и дисклеймер «не публичная оферта».
- Закрытые сделки показываются с фактическим результатом, включая убыточные.
- Английская версия содержит фразу об ответственности инвестора за законы страны проживания.

Форма запроса приглашения: три обязательных подтверждения (высокий риск; статус КИ/ангела или готовность подтвердить; не заявка на инвестирование). Бэкенд должен сохранять текст согласий, дату и время, IP.

## 5. Кабинет участника

Макет — `mockups/02-participant-cabinet.html`, каталог сделок — `mockups/01-deal-catalog-participants-only.html`.

### 5.1 Онбординг кандидата
1. Запрос приглашения → менеджер назначает разговор.
2. Загрузка документов: удостоверение личности, подтверждение статуса КИ или бизнес-ангела, анкета источника средств.
3. Проверка комплаенсом, статус «подтверждён / отклонён / нужны документы».
4. Электронное подписание договора об организации венчурного фонда.
5. Открытие кабинета.

### 5.2 Каталог действующих сделок
Карточка: название, объект, инструмент (мушарака / мурабаха / иджара / истисна / соглашение о будущей доле), срок, размер сделки, собрано, доля участников в прибыли, дедлайн сбора, документы, заключение шариатского совета, отметка «связанная компания» с результатом голосования.
Фильтры: тип, срок, инструмент, сезонность.
Показатель доходности — только «расчёт управляющего» с тремя сценариями (базовый, пессимистичный, стресс) и обязательной пометкой «не гарантия».

### 5.3 Участие в сделке
- Заявка на сумму → проверка лимита (не более 40% сделки на одного участника) → подписание приложения к договору по сделке → вызов капитала с реквизитами счёта сделки → подтверждение поступления бухгалтером.
- Если к дедлайну сумма не собрана — автоматический статус «возврат», уведомление, возврат средств в 5 рабочих дней.

### 5.4 Портфель
Сводка: вложено, получено прибыли, ожидаемые выходы, распределение по типам. Список сделок с моим чеком, стадией, ходом (процент освоения), расчётным диапазоном.
Валюта отображения: USD / KGS с курсом на дату.

### 5.5 Движение средств
Каждый платёж со счёта сделки: дата, получатель, назначение, сумма, скан платёжки. Поступления участнику: возврат капитала, прибыль, рента, отдельно — доля управляющего.

### 5.6 Отчёты
- По стройке — ежемесячно: освоено, отклонение от сметы, фото, акты.
- По фонду — ежеквартально (законодательное требование).
- Годовой отчёт и аудиторское заключение.
Отчёт публикуется управляющим, участник получает уведомление; факт просмотра логируется.

### 5.7 Голосования
Обязательные: сделки со связанными компаниями, изменение договора фонда, досрочная ликвидация. Порог и кворум — по договору. Результат фиксируется с составом голосовавших.

### 5.8 Доска предложений
Участник может выставить долю в сделке другим участникам. Управляющий не выкупает и не гарантирует выкуп. Передача — через подписание переуступки.

### 5.9 Документы
Договор фонда, приложения по сделкам, заключения шариатского совета, отчёты, налоговые справки (на английском для участников из США).

## 6. Админка управляющего
- Сделки: создание, стадии, смета, сценарии, документы, вызов капитала, распределение результата.
- Участники: реестр, статусы KYC/КИ, лимиты, история.
- Платежи: ввод платежей по сделке с загрузкой платёжек, сверка с банковской выпиской.
- Отчёты: шаблоны месячного и квартального отчёта, публикация.
- Голосования: создание, порог, итоги.
- Реестр связанных компаний.
- Журнал действий (кто, что, когда) — неизменяемый.

## 7. Жизненный цикл сделки

`Черновик → Расчёт → Шариатский совет (одобрено / доработка) → [Голосование, если связанная компания] → Открыта для участия → Сбор (дедлайн) → Собрана / Не собрана (возврат) → Исполнение (отчёты) → Выход → Распределение → Закрыта`

Переход в «Открыта для участия» невозможен без загруженного заключения шариатского совета. Переход в «Закрыта» — без распределения всем участникам.

## 8. Модель данных (основные сущности)

- `Participant` — профиль, статус (кандидат / подтверждён / участник / заблокирован), документы KYC, дата подтверждения статуса КИ, страна резидентства.
- `FundAgreement` — договор фонда, версия, дата подписания, подписанты.
- `Deal` — тип, инструмент, объект, валюта (KGS | USD), бюджет, дедлайн сбора, стадия, доля участников в прибыли, доля управляющего, флаг связанной компании, сценарии.
- `Participation` — участник, сделка, сумма, дата вызова капитала, дата поступления, приложение к договору.
- `Payment` — сделка, направление (расход / поступление / распределение), контрагент, назначение, сумма, скан.
- `Report` — сделка или фонд, период, тип, файлы, дата публикации, просмотры.
- `Vote` — предмет, порог, кворум, голоса, итог.
- `ShariahOpinion` — сделка, консультант, статус, файл.
- `Transfer` — доска предложений: доля, цена, статус.
- `AuditLog` — актор, действие, объект, время, IP.

## 9. Интеграции
- Электронная подпись: облачная ЭП КР для резидентов; для нерезидентов — DocuSign или аналог (уточнить у юриста признание в КР).
- E-mail и SMS-уведомления; вход по одноразовому коду, без паролей.
- Банк с исламским окном: выписка по счёту сделки (сначала импорт файла, затем API при наличии).
- KYC: проверка по санкционным спискам (ручная на MVP, сервис — позже).
- Хранилище документов с версионированием.

## 10. Безопасность и комплаенс
- Двухфакторный вход для управляющего и админки.
- Все документы и отчёты — только за авторизацией; публичный сайт не имеет доступа к данным кабинета.
- Неизменяемый журнал действий; экспорт для аудитора и регулятора.
- Хранение персональных данных по законодательству КР; для участников из США — политика обработки на английском.
- Резервные копии ежедневно, хранение вне основного сервера.

## 11. Нефункциональные требования
- Языки: русский, английский. Кыргызский — публичный сайт, позже.
- Валюты: KGS, USD. Никаких других в интерфейсе и расчётах.
- Мобильная версия обязательна: основная аудитория читает отчёты с телефона.
- Доступность отчётов: PDF-выгрузка любого отчёта и движения средств.

## 13. Открытые вопросы к юристу
1. Порядок учётной регистрации в реестре (ст. 11.5) — принят ли подзаконный акт.
2. Критерии бизнес-ангела отдельно от квалифицированного инвестора.
3. Допустимость финансирования оборотного капитала стартапа (мурабаха под рассрочку материалов) как «иного вида финансирования» по ст. 9.8.2.
4. Признание иностранной электронной подписи для нерезидентов.
5. Соотношение статуса КИ по праву КР и accredited investor по праву США для участников из США.
